# 第 7 步 pilot v3 计划（待批准）

2026-10-25。依据 [pilot v2 结果](terrain_controller_pilot_v2_a100_20261025.md)：6 项验收通过 5 项，只剩着地脚速度（0.174 m/s，门槛 0.068 m/s）。本计划只改滑步代价和它的评估方式，需用户批准后启动。

## 1. 为什么脚还在滑

1. **代价可以被绕开。** v1/v2 的滑步代价是"模型预测的着地概率 × 脚底速度²"。模型把着地概率预测得低一些，代价就变小，不必真的把脚停住。
2. **代价太轻。** 0.17 m/s 时代价约 0.03，远小于其他项。
3. **评估口径偏严。** 评估用源动作的着地标记去看生成动作的脚。生成步态只要比源动作早或晚一两帧，摆动中的脚就会被算作"着地却在动"。

## 2. 改动

| 改动 | 代码 |
| --- | --- |
| 滑步代价改为几何判定：脚底在这一帧和上一帧都离表面 3cm 以内（平滑过渡，宽度 1cm），就按着地计算速度²。与模型预测的着地概率无关 | `--skating-mode geometric` |
| 滑步权重 1 → 100，即 0.1 m/s 时代价约 1 | `--skating-weight 100` |
| 评估另加"各看各的脚"口径：生成动作和源动作各自取离表面 3cm 以内的脚底，比较水平速度；原口径保留作对照 | `evaluate` 新字段 `*_grounded_sole_*` |

其余设置与 v2 相同（一步监督混合 1.0，穿透权重 2500）。

## 3. 运行方式与预算

与 v2 相同：从 v1 的 `phase0_teacher.pt` 恢复，跑 loop:4/8/16 各 500 次，共 1,500 次更新；A100 两卡，每卡 512；上限 2 小时，预计约 30 分钟。v1、v2、v3 共享同一个起点。

## 4. 验收

与 v2 第 4 节相同，只是着地脚一项改为：**各看各的脚口径下，生成动作着地脚速度中位数 ≤ 源动作同口径值 × 1.5 + 0.05 m/s**，且生成动作的着地脚比例不低于源动作的一半（防止模型靠"永远不落地"通过）。源动作着地标记口径继续报告，但不作为门。

另单独报告 wall_contact 组（v2 中 7 个窗口有 5 帧穿透），以及与 v2 同更新位置的对照。
