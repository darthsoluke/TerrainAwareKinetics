# 第 7 步 v6 计划：运行时脚锁评估（A）与相位无关接触的闭环对照（B）

2026-10-27。依据 [pilot v5 执行记录](terrain_controller_pilot_v5_a100_20261025.md)。用户已批准 A、B 两组实验。

## 1. v5 说明了什么

v5 的稳定性改动有效：1500 次更新全程有限，没有触发发散保护，critic 损失中位数 0.25。但模型学会了少走路。

- 总体 16 帧根漂移 P50 为 3.65cm，看似通过；拆开看，平地移动组（flat_control）为 **39.1cm**，蹲行组（crouch）为 **20.5cm**。同位置的 v2 分别为 1.47cm 和 1.25cm。总体中位数被四足、跪姿、匍匐等移动很少的组拉低了。
- 转向慢跑的接触图里，生成骨架的腿几乎不摆，从第 5 帧开始落后。侧移停止窗口中，右脚全窗口速度 0.012m/s，源动作为 0.268m/s。生成动作的几何着地比例为 45.6%，源动作为 32.3%。
- 训练日志中位数（第 2875–3000 次）的加权贡献：支撑 0.083、滑步 0.043，合计高于模仿的 0.057。策略损失约 6.9，其中 16 步代价约 3.2，其余约 3.7 来自 critic 的 bootstrap。

判断：v4/v5 用源动作的接触时刻约束生成动作的脚。一旦生成步态与源动作相位错开，源动作标记着地的那一刻，生成的脚可能正在摆动，于是被惩罚；最便宜的应对是不迈步。bootstrap 又把"未来代价低的状态"（静止）推给策略。v3 用几何着地时模型抬脚作弊，v4/v5 换成源接触后变成了不走路。

验收门的漏洞：只看总体漂移中位数，没有分组门，也没有直接衡量"走没走够"的指标。本计划补上这两项。

## 3. 实验 A：运行时脚锁评估（不训练）

只读检查点，不更新任何参数。一张空闲 A100，上限 30 分钟。

检查点：v1 第 1500 次教师、v2 第 3000 次、v3 第 3000 次、v4 第 1500 次教师、v5 第 3000 次，以及 B 的两个结果（B 完成后补跑同一命令）。

每个检查点 × {16 帧、64 帧} × {原始、显示加锁、回灌加锁}。16 帧使用训练器的固定验证批次（validation、256、seed 1、第一批）。64 帧使用同一切分的 64 帧窗口，同样的抽取方式。

报告：总体与分组的漂移、进度比、穿透、骨盆、两种脚速、着地比例、关节加速度，以及锁的激活比例、IK 残差 P95 / 最大值、单角色加锁耗时。

A 的判读（描述性，不是部署门）：v2 加锁后，若源接触脚速 P50 ≤ 0.03m/s，同时漂移、进度比与原始 v2 相差不超过 10%，穿透增加不超过 0.5 个百分点，IK 残差 P95 < 1cm，则把"v2 主干 + 运行时脚锁"列为当前候选。显示加锁和回灌加锁分别判读。

## 4. 实验 B：两组闭环对照训练

两组共用的设置（与 v2 相同的起点和主干设置，只改接触方案）：

- 起点：`runs/tmt_pilot_v1/phase0_teacher.pt`（v2 的同一起点，不含 v4 的支撑脚教师项）。
- 阶段：`loop:4:500 loop:8:500 loop:16:500`，共 1500 次新增更新。
- 一步监督混合 1.0，支撑脚教师项 0。
- 接触来源 `predicted`，接触率锚权重 5，支撑 200，滑步 20（contact 模式），穿透 2500。
- 三项代价封顶、梯度退出阈值与 v5 相同。critic 归一化。
- A100 两卡，每卡 512；每组上限 2 小时。两组顺序执行，合计上限约 4.3 GPU-hours。

| 组 | 区别 |
| --- | --- |
| v6a | bootstrap 开：预热 250 次，估计值封顶 50 |
| v6b | `--no-bootstrap`：只用 16 步内的代价 |

每组正式训练前：相关测试全部通过（含 `tests/test_foot_lock.py`）；双卡两步预检（参数一致、两个反向完成、数值有限，输出删除）。

## 6. 结果决定什么

- A 达到判读标准、B 都未通过：以 v2 + 运行时脚锁作为候选，进入长时段与指令切换评估；B 的问题单独分析。
- B 某组通过：比较它与 v2 + 脚锁在同一张表上的结果，再决定主干。
- v6a 与 v6b 的差别用来判断 bootstrap 是否推动"少走路"。
- 任何结果都不部署；下一轮训练另写计划。
