# 第 7 步 pilot v5 计划（已批准；反向预检失败，已修复待重跑）

2026-10-25。依据 [pilot v4 结果](terrain_controller_pilot_v4_a100_20261025.md)。用户已批准本计划，2026-10-26 执行准备与测试。

执行状态：84 项测试通过；补充 CPU 零更新检查发现 normalized critic 的 `scale` 原地更新破坏 bootstrap 反向传播，后续预检与正式训练停止。新增训练消耗为 0，详见 [v5 执行记录](terrain_controller_pilot_v5_a100_20261025.md)。

修复（2026-10-26）：这是控制器代码的错误，不是数据或计划的问题。`Critic.frozen()` 用 `self.scale.detach()` 作乘数，它与缓冲区共享存储；`loss()` 随后原地更新 `scale`，策略反向时版本号不符。现在 `frozen()` 与 `forward()` 都乘以 `scale` 的快照（`clone()`），本次前向用到的尺度不再被后续更新改动。新增测试按训练器的实际顺序运行 `frozen → loss → policy.backward() → critic_loss.backward()`，以及开启 normalized critic 与 bootstrap 的完整 `closed_loop_step` 反向。计划、预算与验收不变，修复后重新执行预检与本计划。

## 1. v4 说明了什么

- **一步监督阶段的支撑脚项有效**：第 1,500 次时贴地脚速度 0.052 m/s，v1 同位置 0.170 m/s；贴地比例 33%，与源动作一致。代价是一步误差 0.52cm（v1 为 0.34cm）、穿透 18.8%（v1 为 11.1%），闭环阶段一般会把这两项拉回来（v2 经验）。
- **闭环阶段发散**：进入 loop:8 后输出尺度急剧变大，第 2,000 次评估的根节点漂移已到 6.5 米，critic 损失到 1e19–1e26，最终评估时表示转换断言失败。
- **原因判断**：
  1. 代价没有上限。生成动作一旦偏离，支撑代价按"悬空距离² × 2500"增长，1 米就是 2,500；穿透、滑步同理。少数坏样本主导整批梯度。
  2. critic 直接回归这些无界代价，自身发散后，用它估计 16 帧以后的代价（bootstrap）又把错误的梯度传回策略，形成正反馈。
  3. 缺少发散保护，评估异常直接让训练崩溃，最后 250 次更新没有保存。

## 2. 改动

| 改动 | 参数 |
| --- | --- |
| 每步代价封顶：悬空距离 ≤ 0.1m、穿透深度 ≤ 0.1m、着地脚速度 ≤ 1 m/s。偏离很远时梯度不再随距离增长 | `--support-gap-clip 0.1 --penetration-depth-clip 0.1 --skating-speed-clip 1.0` |
| critic 归一化：学习"代价 ÷ 运行中的平均代价"，损失量级稳定 | `--critic-normalized` |
| critic 预热：前 250 次闭环更新只训练 critic、不用它的估计；估计值封顶 50 | `--critic-warmup 250 --bootstrap-cap 50` |
| 发散保护：裁剪前梯度范数连续 25 次超过 1e4 即停止并保存 `diverged.pt`；评估出错时所有卡在同一次更新停止并保存 | `--abort-grad-norm 1e4 --abort-patience 25` |

其他设置同 v4：一步监督混合 1.0、支撑脚项 1.0、源动作着地标记、支撑 2500、滑步 100、穿透 2500。

## 3. 运行方式与预算

从 v4 的 `phase0_teacher.pt`（第 1,500 次，支撑脚项已生效、已通过额外门）恢复，只跑 loop:4/8/16 各 500 次，共 1,500 次更新。A100 两卡，每卡 512，上限 2 小时，预计约 30 分钟。

## 4. 验收

同 v4 第 4 节（不含已通过的一步监督额外门）。另要求：全程没有触发发散保护，critic 损失（归一化单位）在最后 250 次更新的中位数 < 10。
