# 训练到推理的配置与架构审阅

日期：2026-10-18，Asia/Singapore。

## 结论

当前优先级是**训练推理分布对齐、物理空间目标、全身接触与三维场景表示、指令调度**。扩码本值得做容量对照，但它既不能替代接触监督，也不能单独修复闭环反应迟缓。

本轮读取了实际 bundle 与最终 checkpoint 的 CPU 元数据、量化器 EMA 缓冲、阶段训练源码、推理及传输源码，并复用了已有质量和耗时结果。当前两个地图服务 PID 60524、115796 的命令行与交付记录相符。没有运行新模型推理、训练、旧路线评估或修改服务。

实际配置见结构化快照：`${PROJECT_ROOT}/docs/training_inference_config_snapshot_20261018.json`。数据与相关论文见[全身场景方法审阅](whole_body_scene_methods_datasets_review_20261018.md)。本报告按模型实际执行路径审阅，不把未调用的历史实验模块计入当前能力。

## 训练与推理对齐

### Root 教师与动作历史

正式训练从源窗口提取前 4 帧。Pose 所见完整 Root 轨迹及高度也来自源动作；线上这些量来自模型。精确的接触动作对 Root 的几厘米位置差、时序差和身体姿态差都可能敏感。

建议分两步处理。先固定 codec，在 Pose 训练中加入与标签可兼容的预测 Root 条件，明确区分源轨迹标签与经过教师重规划得到的匹配标签。再加入生成 history 的短闭环课程，通过离线教师、可微几何目标或匹配恢复目标监督后续动作。不能简单把偏离路径的 history 与原源动作硬拼接，造成不可能的瞬时恢复。

[CLoSD](https://arxiv.org/html/2410.03441v1)的规划执行闭环提供相关训练设计，但我们的在线出口可保持运动学模型；物理模块可以只承担离线教师和验证。

### 掩码与四轮生成

当前训练先随机选 focused token，再将其中 80% MASK，剩余部分随机改错或保持正确。正式调用 `pose_teacher` 没有开启 `all_mask`。而推理每次重规划从全 MASK 开始，经过四轮 argmax 和置信度重选。

建议保留当前随机掩码任务，同时显式加入全 MASK 起始样本，以及模型自己第一至第三轮生成的部分 token。评价既看 CE，也看四轮最终解码的接触、边界和身体几何。仅降低 CE 不能确定某一 token 错误是否造成严重穿透。[训练掩码](../../motionbricks/motion_backbone/models/pose_model.py#L289)、[推理初始化](../../motionbricks/motion_backbone/inference/motion_inference.py#L339)。

### 观测分布与窗口长度

离线缓存使用源终端指令方向采样；当前 actor 使用预测 Root 曲线，12/16 前瞻还把近远站点混入同一区域。训练时的空间布局与线上语义不同。新数据接口应绑定采样策略版本，训练中覆盖预测路径偏差、查询尺度、身体部位和站点时间。

正式所有阶段固定 8 tokens/32 帧，配置支持 3..16 只是网络容纳范围。当前双时域让执行回到已训练的 8，而长 Root 仍主要承担未经同分布训练的观察假设。若继续保留 12/16，需训练匹配的长 Root 与观测分布，并用正确训练的可变长单时域作基线。

更远期可增加轻量接触阶段与进度状态，避免所有时间信息都依赖 4 帧姿态重新推断。先做辅助条件分支，不立即把所有网络换成长 history Transformer。

### 指令语义

当前目标是“窗口末端应达到的速度”，不是“现在开始保持该速度”。这使模型可以把加速安排在较晚位置。建议保留目标速度，同时引入明确的指令持续时间、进度或阶段条件，并使用起步、停止、转向以及接触准备的真实或教师轨迹训练。攀爬进一步需要三维目标表面和接触意图，水平速度不能独立指定这些任务。

## Codec 与损失

### 容量与实际使用

最终 checkpoint 的码本形状确认为 `[8,10,32]`。保存的 EMA cluster mass 全部大于重置阈值，最小 6.81；按这些质量归一化得到的每头熵困惑度为 8.30 到 9.63，接近每头 10 项上限。这是 EMA 统计，尚未替代按技能计算的新 token 使用分布。

因此优先做容量实验，而不是先处理“死码本”。建议对照 10 与 128 项；若 128 在复杂接触重建上继续受限，再试 256。保持 latent 256 维、8 头和时间下采样不变，以便隔离容量因素。同步比较重建误差、接触和穿透、量化前后差距、Pose 预测难度及推理成本。

每头 128 的输出共 1024 类，每头 256 共 2048 类，当前为 80 类；它们不是把整个 141M Pose 网络放大同样倍数。扩码本会改变 codec encoder/quantizer/decoder 的训练问题，随后需要重新冻结码本、生成标签、初始化 Pose embedding 与输出头并重训 Pose。Root 可作为 warmstart，但要重新核对共享场景与运动表示契约。

**256 项还涉及整数表示。** 当前通过 `nb_code=K**8` 配置，并将各头压成单一整数。`256**8=2**64`，超过有符号 int64 的范围。应显式配置 `entries_per_head`，编码、缓存、解码和统计都保留逐头索引，取消不必要的整体索引路径。[量化器](../../motionbricks/vqvae/neural_modules/quantize_cnn_multihead.py#L53)。

Residual VQ、[FSQ](https://arxiv.org/abs/2309.15505)或连续 latent 可以作为后续对照。当前没有必要同时替换所有量化设计；[MotionBricks](https://arxiv.org/html/2604.24833v1)本身也比较过 FSQ 与 VQ，应首先解释原结构在我们的数据与目标上哪里不足。

### 当前损失与实际动作质量

codec 当前权重是 normalized reconstruction 1、commitment 0.02、skating 0.01、joint velocity 2。Root 使用轨迹回归，Pose 使用 token CE。没有全身场景穿透、扶撑/手膝接触或抓握目标。

已有固定窗口诊断显示 codec 的腿部重建本身存在约厘米级残差，源动作重建也有穿透；输出坐标中的局部梯度还显著集中在 Root 特征。下一版应分别记录旋转、Root、FK 位置、接触和几何项的物理量与梯度，而不是只调一个总 reconstruction 系数。已有目标诊断：`${PROJECT_ROOT}/out/pfnn_mixed_20261015/final_codec_objective_v1-summary.json`。

推荐目标组合是：原动作重建与量化约束、米制 FK 位置、接触状态分类、接触锚点间隙、指定接触区域相对滑动、非接触身体表面穿透，以及新生成帧与已执行前缀的连续性。先选有可信场景和接触标注的样本；训练可采用分部位表面采样控制成本，验收仍使用完整 18056 顶点及原 8 substeps。

### 防滑掩码存在漏惩罚风险

防滑项使用预测接触，而 `inverse` 将其按 0.5 硬阈值转成 bool。若真实支撑脚被预测成非接触，防滑惩罚会漏掉该段；硬阈值本身不提供直接降低接触值的梯度。接触通道仍受到重建监督，但这与稳定的支撑区域速度监督不是同一目标。

建议用有效的源或物理教师接触掩码计算训练防滑，并单独监督接触分类；全身滑动接触和固定支撑采用不同定义。[损失实现](../../motionbricks/vqvae/models/motion_vqvae.py#L304)、[阈值实现](../../motionbricks/motionlib/core/motion_reps/motion_reps_base/seperate_root_local_body.py#L251)。

## 全身场景架构

### 三维表示与采样分辨率

当前三维 SDF 来自高度场实体，能描述台阶实体，但不能表示独立顶部、悬挑和多层通道。纵向范围为 Root 上下各 2 米，只有 8 个采样层，层距约 57 厘米；身体横向间隔约 23 厘米、走廊横向约 20 厘米。距离值可传递邻近表面信息，但这种分配对小手掌支撑、头部净空等细节很粗。

建议使用真正三维几何，保留低成本粗观测，再给手掌、前臂、膝、足底、肩背和头部加入随预测动作移动的查询。输入包含身体部位、预期时间、接触类型和有效性，避免仅用 region ID 区分用途。近远分配先采用固定预算的可解释规则，再比较学习式分配；当前固定 4 近加 4 远作为基线。[当前采样器](../../motionbricks/data/unified_scene_field.py#L81)。

### 场景编码与冻结顺序

目前共享三维 encoder 主要接受 Root 损失的训练，codec/Pose 阶段冻结。这样保证阶段稳定，但其表示未必保存手掌、膝、肩背所需信息。建议在新管线先用 Root、动作重建和接触目标联合训练场景表示，再固定版本；各模块通过独立投影读取同一几何记忆。

若在后期继续更新共享 encoder，Root 也要联合对齐或蒸馏，不能只解冻 encoder 却假设旧 Root 条件保持不变。长期可以合并二维高度和三维距离两个历史支路，先做消融确认其互补性，不直接删掉已有支路。

### Root 与接触共同规划

目前远期 Root 的细观察进入 Pose/decoder，并未回流修改当次短 Root。对于全身交互，手够不够到、头能不能通过，会反过来决定 Root 应该到哪里。

建议的新结构为：用户意图与真实历史进入粗场景规划，联合产生短期 Root、接触计划和进度；由这些预测选取精细观测，再生成短期 Pose 与动作。长期状态描述下一次支撑转换，近期状态负责即时响应。初版保留 VQ 与短时执行，不加入运行时 IK、碰撞投影或输出平滑。

重规划需要保持已建立的有效接触阶段，同时允许根据新命令和可行性释放或改计划。阶段信息进入生成模型；不能通过强行锁住输出手脚代替模型学会接触转换。

## 优化与验证配置

### Batch 与学习率

当前每阶段曝光相同，而 Pose 只有 4000 次 Adam 更新。大 batch 的吞吐收益已测得，但没有同数据同预算的小 batch 质量对照。新实验应同时比较同曝光和同墙钟结果，报告 actual updates；不能把更多参考步当成更多优化更新。

建议先小范围比较 global batch 512/1024/2048 与已有 6144 的收敛效率，不要求每个分支都跑完整预算。学习率、warmup 与冻结范围应作为绑定配置；新初始化接触模块与预训练主干可采用不同学习率。AdamW、权重 EMA、混合精度只在独立对照中引入，不与容量和数据改变一起归因。

保持当前 EMA 按样本顺序的实现作为复现基线。如果改为标准多卡同步量化器，应重新定义 EMA 的计数、衰减单位和 dead-code 阈值，不能把串行 EMA 改成并行均值后宣称等价。

### 验证与模型选择

周期验证目前固定每域 128 窗、主要看原生 loss；这适合监测训练，却不足以选择全身交互模型。增加按技能、几何难度和接触部位分层的验证，包含短闭环、起停与跨动作转换；以预先声明的验证指标选择 checkpoint，最终测试只用于最终报告。

报告全身穿透的均值、分位数、峰值和发生时长，接触准确率及滑动、任务成功率和推进速度。响应单独报告输入到第一帧动作变化、规划年龄、计算 P50/P95/P99、ACK 等待和实际播放率。完整路线保留失败，不用降低行进速度或停住来改善几何分数。

### 训练工程

当前缓存固定窗口和观察，难以直接承载变量长度、生成 history 与新三维观测。新增数据版本应缓存原始连续序列、场景绑定和接触，再在取样时生成或版本化缓存所需观察；旧缓存与账本保持不动。

正式输入准备目前通过临时替换 Root、hook 捕获 Pose 并抛出专用异常，且导入 probe 脚本帮助函数。建议抽成纯输入构建函数和明确的 `forward_root`、`forward_codec`、`forward_pose` 训练接口，减少隐式共享状态。新入口导出单份已解析配置，清楚区分模板、checkpoint 和运行时覆盖。

## 推理性能与调度

当前 dual 配置固定近期 8 tokens、4 Pose passes、每 4 帧内部规划、8 帧传输和 30 Hz 播放。前瞻 12/16 时每次规划增加一遍长 Root，仍只解码近期动作。

### 指令刷新不是内部规划刷新

[包内规划](../../motionbricks/data/pfnn_tuning.py#L157)把同一个速度和朝向用于两个子规划。第二次使用第一个子段的不可变生成前缀，并没有再次接收用户输入。当前 nominal 内部规划 7.5 Hz，指令快照仍按 8 帧包更新。

建议先解耦 socket 读取、指令快照、计算完成和 ACK，保持所有状态提交串行，取消的只能是尚未发布的候选。之后比较 4 帧传输与当前 8 帧协议，保持 30 Hz 时钟和事实 history。4 帧可用时间约 133 ms，必须先证明 P95/P99 计算与传输留有余量。[消息处理](../../scripts/soma_lab_server.py#L423)。

### 优先优化几何查询

已有 005 移动 profile 中，每个 8 帧包的两轮 Root 图合计约 6.7 ms、Pose/decoder 图约 22 ms，粗和路径查询在不同档位分别约 35 至 84 ms、29 至 80 ms。stage 样本与整包样本不是同一时刻，不能相加后宣称精确占比；它们已足以支持优先审查几何工作量。[原计时](pfnn_horizon_acceleration_review_20261017.md#L41)。

按顺序考虑：同一观察快照内的查询合批与重复消除、减少 CPU/GPU 同步和小 kernel 调度、把不影响生成的密集调试序列化移出默认热路径、静态几何特征缓存、面向三维网格的高效查询实现。缓存必须绑定场景版本与观察坐标，不能将角色移动后的旧观察当作当前值。

当前相同观察内已有身体与速度区域复用及神经计算图共享，这些收益不重复计入。近似距离场或降低查询数量属于新观察算法，需要质量对照，不按执行等价优化处理。

### 神经网络加速放在第二层

保持当前 FP32、原 token/FK/skin 比较作为基线。待几何瓶颈明确后，再测 BF16/FP16、TensorRT 或更小 Pose student。16 层 1024 宽、四遍 Pose 是潜在压缩目标，候选可以是较浅 student 和两遍生成，但需要蒸馏与闭环质量验证。

当前 Pose 使用双向 Transformer，多轮 masked token 和条件都会变化，不能直接套用文本自回归 KV cache。可缓存静态场景编码；跨步复用动作隐状态或旧 token 则需要专门训练与新执行策略。不能通过启用未经匹配训练的随机采样、减少步数或后处理来隐藏连续性问题。
