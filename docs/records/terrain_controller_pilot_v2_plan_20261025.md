# 第 7 步 pilot v2 计划（待批准）

2026-10-25。依据 [pilot v1 结果](terrain_controller_pilot_a100_20261024.md#10-be5fc1f-pilot)。v1 的 3,000 次更新完成，6 项验收通过 3 项。本计划只改闭环阶段，需用户批准后启动。

## 1. v1 说明了什么

| 现象 | 解读 |
| --- | --- |
| 一步监督阶段结束时一步误差 0.338cm（比"保持上一帧"好 64%），进入闭环阶段后升到 0.66cm | 闭环阶段只优化闭环代价，模型逐渐遗忘一步拟合 |
| 16 帧闭环漂移中位数 13.8cm → 0.85cm，骨盆高度误差 1.28cm | 闭环训练本身有效 |
| 穿透超 2cm 的帧 1.54%；穿透代价权重 100 × 深度²，2cm 时仅 0.04 | 穿透代价相对其他项太弱 |
| "滑步、穿透低于初始值"两条门不通过 | **门设计有误**：未训练模型只是保持上一帧，自然既不滑也不穿透。应该和源动作在同一批窗口上的数值比较 |

## 2. 改动

| 改动 | 代码 |
| --- | --- |
| 闭环阶段每次更新同时加上一步监督损失（权重 1.0），防止遗忘 | `--teacher-mix 1.0` |
| 穿透权重 100 → 2500，即深度 2cm 时代价约 1 | `--penetration-weight 2500` |
| 评估加入源动作在同一窗口上的穿透帧比例和着地脚速度，并按动作组分别报告 | [training.py](../../motionbricks/controller/training.py) `evaluate` |

## 3. 运行方式与预算

从 v1 的 `phase0_teacher.pt`（第 1,500 次更新，一步监督结束）恢复，同一阶段列表，只跑三个闭环阶段：

| 阶段 | 更新 |
| --- | ---: |
| loop:4 | 500 |
| loop:8 | 500 |
| loop:16 | 500 |
| 合计 | 1,500 |

A100 两卡，每卡批量 512；墙钟上限 2 小时。按 v1 计时加上一步监督的开销，预计约 30–40 分钟。这样 v1 与 v2 共享同一个一步监督起点，差异只来自闭环阶段的改动。

## 4. 验收（诊断性）

| 指标 | 通过条件 |
| --- | --- |
| 数值、各卡参数一致 | 全程有限；`rank_parameter_disagreement` 全为 0 |
| 一步全身误差 | 比"保持上一帧"低至少 30% |
| 16 帧闭环漂移 P50 | < 10cm |
| 穿透超 2cm 的帧比例 | ≤ 源动作同窗口比例 + 0.5 个百分点 |
| 着地脚速度中位数（源动作标为着地的帧） | ≤ 源动作同窗口值的 1.5 倍 + 0.05 m/s |
| 骨盆高度误差 | < 5cm |

另报告各动作组的漂移、穿透（含源动作对照）和骨盆误差。不通过则保留结果，不追加预算。
