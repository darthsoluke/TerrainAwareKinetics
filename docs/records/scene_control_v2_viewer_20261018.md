## Playback

The simulation clock is independent of render-refresh frequency and fixed at 30Hz. The first available packet can render immediately; subsequent native frames use 33.333ms deadlines. Adjacent packets retain the same next-presentation deadline, avoiding an extra packet-start wait. A severe timer delay rebases the next deadline instead of bursting or skipping frames. There is no interpolation, smoothing, IK, foot locking, Root rewriting or generated frame.

ACK is sent only after every frame in the packet has passed a successful `renderer.render`, including the last complete vertex snapshot. It contains that packet's exact `packet_id`, full `frame_count` and original revisions. The following packet cannot present before the existing next 30Hz deadline. A renderer exception cannot increment the playback cursor or emit an ACK for the failed frame. The server's independent earliest-ACK boundary is send-start plus `(N-1)/30`, consistent with immediate first presentation. The footer's `HZ` is measured from actual successful presentations, not hardcoded to 30.

Root drives only camera/light following and telemetry. Body vertices and bound terrain are rendered in their received world coordinates. The original model and its motion/terrain quality remain unchanged.

## Read-Only Browser Diagnostics

On the new page only:

```js
const d = window.sceneControlV2Diagnostics();
console.table(d.events.filter(e => e.type === 'command_sent' && e.first_render_at_ms !== null));
```

The function returns a deep copy and has no reset/mutation API or network side effects. Its single shared buffer retains at most **500 events**, across reconnections. `sequence` is monotonic; `session_id` increments on each accepted `ready`, disambiguating session-local packet IDs. Read the snapshot regularly during comparison runs because old events are evicted.

For browser APIs that can inspect DOM but cannot call the window function, open Settings (`#settings-toggle`), then click the file-JSON icon **Export diagnostics JSON** (`#diagnostics-export`). Only that click serializes the current snapshot and reveals the readonly textarea `#diagnostics-snapshot`. Read its standard DOM `value` property:

```js
JSON.parse(document.querySelector('#diagnostics-snapshot').value)
```

The textarea remains a fixed, detached snapshot while playback and the bounded log continue. Click export again to replace it with a fresh snapshot. No per-frame JSON serialization, download, auto-focus, pause, command or ACK change is added. This UI uses the existing vendor's `file-json` icon; the export remains independent of window-function access.

- Every event has `type`, `at_ms`, `sequence`, `session_id`, `scene_revision`, `settings_revision`. Browser timestamps share `performance.now()` and the snapshot's actual `time_origin_ms`.
- `command_sent`: timestamp immediately before the successful WebSocket send call, command ID/intent, `packet_frames`, `lookahead_tokens`. On its first associated successful native render, that retained event gains `first_render_at_ms`, `first_render_packet_id`, `first_render_frame_index`, and **`command_associated_first_render_latency_ms`** (render return minus send start).
- `frame_presented`: recorded only after successful `renderer.render` in native `present`, not camera-only redraws. Includes `packet_id`, zero-based packet-local `frame_index`, `absolute_frame`, `packet_frames`, `command_id`, `command_ids`, `command_sent_at_ms`, `compute_ms`, `is_command_associated_first_render`, and first-render latency on that first event. Command association uses `command_ids[Math.floor(frame_index / 4)]`, including different commands in the two halves of an 8-frame packet. Later settings cannot relabel old frames.
- `plan_received`: accepted packet metadata, command IDs, revisions, packet size and actual server `compute_ms` duration. Server absolute clocks are not mixed into browser elapsed-time calculations.
- `ack_sent` / `ack_received`: actual client send/accepted-receipt timestamps, exact full frame count, packet ID and packet revisions; receipt also includes `committed_frame`. Command receipts, applied settings/pauses and session readiness are retained as small context events.
- `empty_wait`: one coalesced observed wait per revision/phase, only when the next native-frame deadline is due and there is no playable packet. It records `reason` (`ack_receipt` or `packet`), `waiting_packet_id`, `checks`, `last_checked_at_ms`, and eventual `ended_at_ms` / `duration_ms`. Pause/hidden observations close the wait; normal 30Hz cadence waits do not count. Timestamps are actual observation times, not reconstructed/backdated deadlines; ongoing waits retain null end/duration.

The metric is explicitly **command-associated first-render**: send start to the first successful render-return associated by the server's command ID. It does not measure significant pose response or input-to-photon. A command without a rendered association retains null timing; if its send record was evicted, later frames retain the command ID but report null association timing rather than inventing a replacement sample.

Playback deadlines, native geometry, ACK contents and semantic command deduplication are unchanged. Diagnostics and their export stay within the owned viewer files and this report; no service or browser was started or navigated.
