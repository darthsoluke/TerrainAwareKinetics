# 骨骼射线观测与性能约定

2026-10-23。本文说明第 6 步（观测与缓存）候选的身体附近感知方式，以及保证 60fps 的性能约定。这是设计与实现，尚未用于训练。

## 1. 做什么

现有体积观测（[VolumetricEgoSampler](../../motionbricks/data/unified_scene_field.py)）以根节点为中心放三块 8×8×8 点阵。身体附近那一块在匍匐时盖不住头和脚，竖直层距约 0.57m。

[skeleton_ray_sampler.py](../../motionbricks/data/skeleton_ray_sampler.py) 改为从控制器骨骼的节点发射线：

- 节点：头、胸、髋，双手、双前臂、双小腿、双脚、双脚尖，以及大腿、小腿、上臂三段的中点，共 19 个。
- 射线：按角色朝向坐标系的上、下、前、后、左、右、前上、前下，长度 0.5–1.2m，共 49 条（[默认布局](../../motionbricks/data/skeleton_ray_sampler.py)）。
- 每条射线输出 6 维：命中距离 / 最大长度、命中面法向（朝向坐标系）、是否命中、节点是否在实体内部。共 294 维。

前方的指令走廊、实际走廊仍由体积观测提供，用于提前减速、提前下蹲。是否采用、与现有观测如何组合，由第 6 步的对照实验决定（见第 4 节）。

## 2. 性能约定

| 约定 | 做法 |
| --- | --- |
| 形状固定 | 射线数由布局决定；场景实体填充到固定容量 K（默认 64），空位放在远处并屏蔽 |
| 不与 CPU 同步 | 每帧路径没有 `.item()`、`.all()` 检查或按数据分支；输入检查放在 `check_inputs`，只在测试和离线建缓存时用 |
| 解析求交 | 射线与有向长方体的平板法求交，一次张量运算完成 [批, 射线, K] |
| 可录入 CUDA graph | 满足以上三条后，整段观测可以和解码器一起静态重放（仓库已有 [soma_cuda_graph.py](../../motionbricks/data/soma_cuda_graph.py)） |
| 参考实现 | `cast_rays_numpy` 为 float64 参考；测试检查 torch 版与之一致，并与逐点步进的暴力结果一致 |

计算量：批 1 时 49 条射线 × 64 个实体约 3,100 次求交，每次几十次浮点运算。

现有体积观测在每次查询时做主机端有限值检查，会触发 GPU 同步，预计不能直接录入 CUDA graph。计时脚本会如实报告这一点；若最终保留体积观测，需要把这些检查移出每帧路径。

## 3. 计时与门槛

[benchmark_scene_observation.py](../../scripts/benchmark_scene_observation.py) 在部署显卡上计时，用 CUDA 事件逐次测量，报告 P50/P99/最大值：

```bash
python scripts/benchmark_scene_observation.py --device cuda --output obs_bench_3080.json
```

| 项 | 门槛（P99，批 1） |
| --- | --- |
| 射线，CUDA graph | ≤ 0.5 ms |
| 射线，普通执行 | ≤ 2.0 ms |

60fps 时整帧预算为 16.7 ms。观测只能占很小一部分；整帧瓶颈在模型解码和 Python 调度。此前的实时记录在实时预览中约 22–30fps（[joint SDF 结果](joint_sdf_results_20261012.md)），所以 60fps 必须用整帧端到端计时来确认，观测计时只是其中一项。

## 4. 待定

- 节点与射线布局按实验结果调整；改变布局会改变输入维度，需要重新建缓存。
- 地形高度图（下一阶段）的射线求交：高度图已被合并为等高矩形棱柱，可按同样的平板法求交，但需要按角色位置裁剪到固定容量。
- 闭环时节点位置来自模型自己生成的历史姿态；训练时需对历史姿态加噪声或部分使用模型输出。
