# 第 6 步：BONES 动作—场景训练集与在线观测

2026-10-24。地形拟合以 v9 结束（[v9 全量记录](bones_terrain_fit_v9_pro6000_20261024.md)，已知限制见 [方法文档](bones_terrain_method_v2_20261023.md) 第 8、14 节）。第 6 步把 v9 的拟合结果变成训练数据，并确定模型每帧看到什么。尚未在服务器运行。

## 1. 缓存什么，不缓存什么

| 内容 | 处理 | 理由 |
| --- | --- | --- |
| 源动作 | 缓存为原生全局 SOMA30 帧 [F, 366]，构造方式与闭环生成时的 `advance` 完全相同 | 训练时的历史帧和模型自己生成的帧是同一种表示 |
| 场景 | 缓存每个合格变体的长方体（填充到 64 个） | 与射线、距离场代码直接对接 |
| 接触 | 按拟合场景计算脚跟/脚尖：最低点离表面 3cm 内、平均水平速度低于 0.2 m/s | 与场景一致，不依赖旧的弱接触启发式 |
| 摇杆指令 | 沿用 P1 的 `input_intent_labels`：未来 4 帧的平均速度，朝向取 4 帧后；减速到停的区间给零速度 | 与已有训练和评测一致 |
| 身体射线、路径站点射线 | **不缓存**，训练时在 GPU 上在线计算 | 闭环训练里历史来自模型自己，观测必须现算；与运行时用同一段代码 |

坐标只做一次处理：动作和场景一起整体下移，使拟合地面为 y=0。动作本身不改；原生帧经 FK 后与源 FK 差超过 2mm 的片段直接拒绝。

## 2. 选哪些片段

- 默认只用 `environment_explained`（环境可解释）的片段，以及它们被接受的场景变体。
- `geometry_only_low_posture_unexplained`（无环境原因的低姿态，例如原地跪下）可以用 `--include-geometry-only` 另行构建，单独存放，不混入默认训练集。
- 梯子、越障两组在拟合阶段已被排除。

## 3. 划分

按演员划分，同一演员只出现在一个集合里：测试 8%、验证 4%，其余训练。划分由演员编号的哈希决定，可复现。留出录制家族和几何参数区间的划分，在训练评测设计时再加。

## 4. 训练窗口

每个样本：16 帧历史、随后 16 帧目标、对应的 16 个摇杆指令和接触，以及该片段的一个场景变体（由样本序号固定，保证每轮可复现）。要求窗口内每一步的指令都有效。

## 6. 审计看什么

- 各组头顶净空的分布：匍匐、手膝组应明显低于平地组。这是"观测里确实含有姿态线索"的直接证据。
- 射线节点落在实体内的比例：源动作穿透不超过 2cm，节点是关节中心，应接近零。
- 接触率、指令速度分布。
- 每个样本的观测耗时；单角色一步（FK、射线、站点、模型、追加帧）的耗时；批量短闭环加反向传播的耗时。
