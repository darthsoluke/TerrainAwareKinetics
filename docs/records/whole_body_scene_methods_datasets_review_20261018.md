# 全身场景交互的方法与数据审阅

审阅日期：2026-10-18，Asia/Singapore。

目标是可交互的全身场景动作生成：行走、扶撑翻越、爬上平台、爬行穿过低顶空间，以及这些动作之间的连续转换。当前 SOMA 与 MotionBricks 系统作为起点，保留 30 Hz 播放和快速输入响应。

本轮核对了论文的方法、部分实验及附录、作者仓库和数据发布说明，并对照本地数据接口。公开数据的规模采用作者口径；逐片接触质量、动作数量及新数据到 SOMA 的转换质量留给样本验收。未下载大型数据、运行作者模型或启动训练。

## 主要判断

1. **数据采用互补组合。** PARC 提供攀爬、翻越种子；LINGO 的动作表明确包含 crawl，优先核查其爬行与过渡片段；TRUMANS、CIRCLE 补充全身与三维空间的关系。不能用总小时数代替目标动作覆盖率。
2. **合成采用两种机制。** 接触保持的几何变形扩展已知技能，生成器与离线物理跟踪扩展动作组合。前者借鉴 OmniRetarget，后者借鉴 PARC；最终在线角色仍可采用纯运动学生成。
3. **近远观测已有直接先例。** LINGO 已同时观察当前和前瞻位置。接触阶段也已有 WoCoCo，接触提示与场景重建已有 SceneBot。研究贡献需要落在具体的观测分配、接触进度保持和响应质量上。
4. **当前系统已有未利用的数据。** PARC 的 15 路身体接触已被保存在旁路文件中，正式 MotionBricks 特征仍只使用 4 路足部接触。先补全接触表示和监督，再决定是否扩大码本。

| [TRUMANS，CVPR 2024](https://arxiv.org/html/2403.08629v1) | 自回归扩散，围绕子目标查询局部占据体素，逐帧动作条件带有进度 | 局部场景编码和动作进度是重要对照；动作表示转换及物体后处理也要计入系统成本 |

| [OmniRetarget，ICRA 2026](https://omniretarget.github.io/) | 交互网格保持人体、物体、地形关系，约束优化用于转换与增广 | 适合离线生成几何变体；要适配 SOMA，而不是把 G1 关节轨迹直接当成人体标签 |
| [MotionBricks，SIGGRAPH 2026](https://arxiv.org/html/2604.24833v1) | 多码本动作表示及 Root、Pose、decoder 分层生成 | 保留快速动作主干；原文指出连续地形数据不足，也已讨论重规划造成动作起始阶段滞留 |
| [SceneBot，2026 预印本](https://arxiv.org/html/2606.27581v1) | 参考动作与身体接触提示共同驱动物理跟踪；由动作反推场景交互图 | 接触条件和反向构造场景的重要近邻；低层跟踪与从意图自动生成接触计划仍是不同任务 |

### 三个会改变方案的细节

**LINGO 已有双区域观测。** 其两个体素块分别位于当前骨盆附近和前瞻区域；行走时前瞻块沿目标方向前移，交互时放到目标物体处。因此，“当前看一块、前面再看一块”应作为已有基线。我们的候选差异是由预测身体部位和接触事件决定查询位置，并在固定查询预算内分配算力。[论文第 3.3 节](https://arxiv.org/html/2410.03187v1#S3.SS3)

**PARC 是离线数据扩增的直接参考。** 其原始数据约 14 分 7 秒，有人工重建的配对地形和接触标签。论文长路线配置每次生成 0.5 秒动作、候选 batch 32，A6000 上约需 12 秒；这个设置适合离线教师。物理记录阶段可能从较晚帧开始保留成功后缀，导入时要记录起点、原始时长和截取规则。[论文第 6.3、7.1 节](https://arxiv.org/html/2505.04002v1)

**SceneBot 仍不能直接填满三维场景空缺。** 它从手腕、足部、骨盆的时序关系建立交互图，重建地形和物体，但地形部分仍采用 2.5D 高程图。它适合借鉴“动作到接触到场景”的数据构造方式；低顶通道需要三维实体几何。作者项目页目前仍标注代码和数据 Coming Soon。[方法第 3.1 节](https://arxiv.org/html/2606.27581v1#S3.SS1)、[发布状态](https://ericcsr.github.io/scenebot/)

### 补充近邻

- [AAMDM，CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/papers/Li_AAMDM_Accelerated_Auto-regressive_Motion_Diffusion_Model_CVPR_2024_paper.pdf)：快速生成与后续精化的组合，可作速度质量对照，重点不是全身场景数据。
- [MotionStreamer，ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/papers/Xiao_MotionStreamer_Streaming_Motion_Generation_via_Diffusion-based_Autoregressive_Model_in_Causal_ICCV_2025_paper.pdf)：因果动作压缩和增量生成，是审视固定窗口与流式响应的相关工作。
- [UniHM，2025 预印本版本](https://arxiv.org/html/2505.12774v1)：连续全局运动与离散局部动作混合表示、LFQ-VAE 和场景条件。用离散码本做场景动作本身不是新的贡献。
- [DeSeG，2026 预印本](https://arxiv.org/html/2607.05787v1)：分离语义意图与几何约束，把几何惩罚加入训练，减少测试时优化。应比较其实际发布实现与我们的系统延迟，而不是直接采用论文自报改进百分比。

LINGO 的 crawl 类别来自论文附录动作表。下一步需要统计该类独立录制数、时长、手膝接触以及是否真的包含低顶通道；这决定它能否独立支撑爬行任务。其公开 README 中的手部交互帧也不等于所有身体部位的逐帧接触序列。[动作表](https://arxiv.org/html/2410.03187v1#A2.SS2)、[发布字段](https://github.com/mileret/lingo-release)

TRUMANS 的接触是由拟合人体网格与场景的距离、朝向等计算得到。其判定还会把部分物体内部顶点标为接触。我们应分别保存原标签和目标骨架上的重新测量，避免把已有穿透当成理想接触监督。[附录接触定义](https://arxiv.org/html/2403.08629v1)

## 当前实现的具体缺口

### 接触信息没有进入全身监督

[PARC 配对读取器](../../motionbricks/data/parc_paired_source.py#L194)读取 15 路身体接触。[数据构建器](../../scripts/build_parc_native_dataset.py#L877)明确保存这些旁路标签，并设置 `used_as_mb_contact_loss=False`。正式动作特征使用重新计算的四路足部接触。

所以第一项数据工作是检查现有接触与手、前臂、膝、骨盆的对应关系，定义全身监督通道。已有转换和审计结果继续保留，只审查新增用途所需字段。

### 几何查询仍依赖高度场

[场景入口](../../motionbricks/data/unified_scene_field.py#L62)从高度场构造距离查询；[Root 路径采样](../../motionbricks/data/root_path_terrain.py#L54)沿水平路径调整观测。三维查询点本身不能让底层高度场拥有顶部、洞穴或多层结构。

新场景接口需要直接查询三维网格或体积场，并支持场景对象 ID、局部接触锚点、法线及有效区域。动态物体的锚点还必须随其变换更新。

### 手部动作和身体外形需要一起验收

[当前 PARC 到 SOMA 的转换](../../motionbricks/data/parc_soma_retarget.py#L241)只把手腕作为任务锚点。手腕到达边缘，不代表手掌能够支撑，也不提供指尖抓握。首轮选择大面积扶撑翻越、平台攀爬和手膝爬行，接触检查落实到对应表面；精细抓握和自由攀岩另设任务。

### 动作主干需要适配任务条件

当前速度和朝向接口适合行走。全身交互增加目标表面、接触状态与动作阶段后，Root 与 Pose 的训练条件也应改变。先测现有 codec 对目标动作的重建、接触和穿透上限，再决定只训练条件模块，还是同时更新 codec。若改变 encoder 或码本，需要重新冻结 codec 并生成 Pose 标签。

## 合成数据路线

### 路线一 保持动作的非接触几何增广

从已配对的动作出发，在不改变支撑和身体扫掠空间的区域改变背景、障碍和通道形状。对爬行，可以在真实动作上方添加满足净空的顶板，得到与动作相容的场景；这只增加环境变化，不能提供“遇到更低顶板后主动压低身体”的动作变化。

用途是扩大观测覆盖、制造可解释的净空测试，成本低。保留原始录制 ID，所有衍生场景归入同一个数据划分。

### 路线二 接触保持的动作与场景联合变形

参考 OmniRetarget，在改变平台高度、支撑面位置或人体尺寸时，联合调整动作，保持手脚与指定表面的关系，同时约束全身穿透、关节范围及速度。官方实现入口是 [amazon-far/holosoma](https://github.com/amazon-far/holosoma)，不是搜索结果中同名的第三方复现。

该工具当前面向机器人。迁移到 SOMA 需要定义人体关节自由度、碰撞代理及接触表面，优化结果再使用完整人体网格检查。转换后只满足运动学约束的样本，与通过物理跟踪的样本分开记录。

### 路线三 生成与物理校正的数据回流

建议流程为：

1. 用通过接触检查的种子动作与场景训练条件生成器。
2. 在预先划分的训练场景中生成新动作、接触计划和过渡。
3. 由离线物理跟踪器尝试执行，记录实际运动、接触、失败位置及完整任务结果。
4. 将合格的实际执行轨迹作为监督数据，保留一定比例的原始动捕。
5. 用独立验证集检查增广是否改善接触、动作自然度与闭环恢复，再决定下一轮规模。

这条路线需要一个与目标人体形态相容的物理教师。直接将 G1 的 `qpos` 转成 SOMA，容易把机器人比例和动作限制带入人体。先验证人体代理与完整 SOMA 外形之间的接触差异。

PARC 作者目前建议采用 [MimicKit](https://github.com/xbpeng/MimicKit) 作为新的运动跟踪实现；原 PARC 的 Isaac Gym 跟踪模块不是唯一选择。优先复用现有可运行的模拟与记录基础，再测吞吐和纠错成功率，而不是先迁移整套基础设施。[PARC 官方说明](https://github.com/mshoe/PARC)

新动作可以因失败而不进入训练集，但其失败记录、生成分母和筛选规则必须保留。完整路线评估固定起点，不能用截断成功后缀代替完成任务。

### 路线四 少量针对性采集

如果公开爬行动作缺少通道配对或站立与爬行过渡，补采少量固定几何的种子比无限扩增不匹配片段更有效。优先覆盖站立到手膝支撑、通过不同净空、退出后起身，以及左右手起始差异。

VR 辅助 MoCap 可减少场景布置成本，但承重攀爬仍需要真实支撑设施。真人采集应由专业人员设置安全场地、取得参与者同意，并记录实物尺寸与碰撞表面。

## 建议的数据契约

每条样本同时绑定动作、场景和接触，而不是独立存一份动作和一张不相关地图。

| 类别 | 必须保留的内容 |
| --- | --- |
| 来源 | 原始录制、演员、原始帧区间、生成父链、授权来源、捕获或构造环境类别 |
| 人体 | 骨架、形状、坐标单位、原始时间戳、局部姿态、全局位姿 |
| 场景 | 网格或体积场、对象 ID、逐帧物体变换、有效区域 |
| 接触 | 身体表面区域、对象及局部锚点、开始结束、目标状态与实际状态、标注来源及置信度 |
| 力学 | 摩擦和质量等模拟参数；有实测或仿真力时另存，未知时留空 |
| 任务 | 用户目标、技能阶段、进度、完整成功或失败与原因 |
| 质量 | 全身和帧间穿透、接触间隙、相对滑动、关节限制、转换误差 |

接触类型至少区分支撑、扶撑、抓握、触碰和允许的滑动。不能把所有接触速度都强制为零，例如沿表面滑动的前臂与固定支撑的手掌需要不同监督。

划分按原始录制和场景家族进行，所有镜像、重定向和几何变体保持同组。最终测试另外保留新的几何组合、入口状态和完整路线。缺少场景或接触的样本使用有效性掩码，不补成虚构的平地与零接触标签。

## 研究主线与对照实验

### 收窄后的贡献假设

**在固定推理预算内，根据预测的全身接触与碰撞风险选择观测位置，并让长期接触进度与短期动作更新协同，使角色在不同全身交互之间转换时保持低延迟和接触准确性。**

该假设的关键不是新增一个接触变量，而是观测、接触决策与短期执行之间的因果关系。保留粗略空间观测以发现新障碍，再把精细查询分配给即将接触或发生碰撞的部位。

### 最小实验矩阵

| 问题 | 对照 | 指标 |
| --- | --- | --- |
| 预测身体位置是否改善观测 | 当前固定体积、LINGO 式当前加前瞻、Root 路径、全身接触引导；查询预算一致 | 全身穿透、接触误差、任务成功 |
| 接触计划是否提供独立价值 | 无计划、人工计划上限、预测计划；动作主干和数据一致 | 错误接触、接触时序、支撑转换、动作自然度 |
| 长期进度是否减少反复起步 | 每次重新预测阶段、保留进度、事件触发更新；相同命令 | 起步和转换时间、停滞比例、命令响应延迟 |
| 双时域是否超越长度分布修补 | 正确训练的可变长单时域与双时域 | 同质量下延迟、同延迟下质量 |
| 哪种合成数据真正有效 | 原始配对、几何增广、接触保持变形、物理校正；匹配训练曝光 | 未见场景成功率、合成有效率、每有效分钟成本 |

主任务依次为：扶撑翻越、爬上平台、手膝爬行通过低顶通道，再串成含起停和转向的完整路线。侧向空间和顶部净空都要变化。物体搬运随后扩展，不与首轮静态通行同时扩大范围。

评价记录完整身体表面及帧间扫掠，分别报告期望接触与意外碰撞。对比的速度、实际进度、推理设备、模型计算、场景查询和传输预算保持明确；主动停住不算改善通行质量。原有峰穿透 2 cm、完整 18056 顶点与 8 substeps 检查继续用于当前人体系统，并增加全身接触指标。

## 下一步执行顺序

1. **新用途样本审查。** 复用现有 PARC，核对攀爬翻越及其 15 路接触；取得授权的 LINGO 小样本，统计 crawl 和过渡；用 TRUMANS 或 CIRCLE 样本测试三维场景格式。不重建已经完成的原训练缓存。
2. **零更新可行性检查。** 同一 SOMA 骨架下比较源动作、转换动作、codec 重建的接触与全身净空，判断瓶颈在数据转换、codec 还是条件生成。
3. **小规模离线增广试验。** 各选有限的平台与通道变体，比较仅几何变化、联合动作变形的成本和保真度；如需训练物理教师，单独给出环境步预算。
4. **确定模型改动和训练预算。** 接触监督、场景编码、Root/Pose 条件与 codec 是否重训由上述结果决定；再明确样本曝光、实验分支和停止条件。
5. **同预算消融与完整路线。** 用冻结测试划分评价方法贡献，最后才进入在线交互版本。

本轮优先级是 **PARC + LINGO + 三维场景样本接入，再验证接触保持增广**。先回答数据是否足以支持目标技能，以及现有 codec 是否能保真重建；避免在尚未确定的数据问题上扩建整个模型。
